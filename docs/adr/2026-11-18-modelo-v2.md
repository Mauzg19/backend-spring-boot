# Modelo de ventas v2

Se adopta `demanda-mlp-v2-seed42`, seleccionado por MAE de validación entre cuatro configuraciones prefijadas y la referencia v1. Conserva las 13 entradas y las tres capas densas del evaluador Java. Cambia a arquitectura 13 → 32 → 16 → 1, sin Dropout, L2 0,0001 y Adam 0,003.

La decisión reutiliza el CSV sintético, sus particiones cronológicas, la normalización ajustada en entrenamiento y el contrato JWT existente. La comparación retrospectiva en la prueba de v1 reduce MAE de 3,1716 a 3,0504 unidades. La confirmación de generalización requiere un período futuro independiente.

El informe identifica el modelo y declara `historyMetric` y `training` para que React describa las métricas y la arquitectura recibidas. Flutter muestra el identificador y conserva compatibilidad con reportes sin ese campo. Los pesos y el informe deben tener la misma identidad al iniciar Spring. El Keras y los scripts permiten reproducir el entrenamiento fuera del servidor.

Para revertir se deben restaurar juntos pesos e informe de `mineria/referencia-v1/`, reconstruir el JAR y ajustar las referencias numéricas de las pruebas. Las interfaces conservan el contrato de las solicitudes. La inferencia en el servidor evita duplicar el modelo en cada cliente.
